# Public project instructions

- Publish project source, necessary resources, synthetic tests and impersonal documentation only.
- Never commit or upload real savegames, backup libraries, restore candidates, personal exports, screenshots of real worlds, private research logs or credentials.
- Exception: an explicitly approved, reviewed demonstration world may be distributed as a separate versioned demo asset. Do not treat this as permission to publish other worlds or entire libraries. Keep demo downloads optional, verify checksums and never overwrite existing library entries or restore to a device automatically.
- Reviewed screenshots of the explicitly approved demo world are allowed in the documented gallery. Check visible content and image metadata, record the app/demo version, and retain the exact-file checksum allowlist. This exception never permits screenshots from a private library or live personal world.
- Do not include personal names, email addresses, local user paths, device identifiers or details of any real player's world, including world IDs, seeds, names, coordinates and inventory contents.
- Use fabricated values for all test fixtures and teaching examples, except explicitly reviewed and labeled excerpts of the approved demo. Do not copy private workspace AGENTS.md files into this repository.
- Review the exact staged files, archives and metadata before every commit, push or release. Use an explicit file selection; never publish an entire private working directory.
- Use a public account name and GitHub noreply email for Git authorship.
- Keep the change log and backlog in English, with newest versioned entries first.
- Preserve existing license and resource provenance notices.
- Before editing any actual Quest save files during separately authorized local work, stop the game and create a restorable backup. Never use a real device or private savegame in CI.
- Keep existing backup/restore verification and file-permission safeguards intact.
