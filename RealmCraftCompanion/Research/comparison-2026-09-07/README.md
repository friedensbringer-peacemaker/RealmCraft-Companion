# Minecraft / RealmCraft VR checklist — review 2026-09-07

Scope: selected vanilla Minecraft Java/Bedrock counterparts versus RealmCraft VR release evidence through 1.0.3 (2026-08-20). This is a content reference, not a complete catalog, a test on a connected headset, or a count of features in a saved world.

The live data is `Resources/MinecraftChecklist.json`; this folder preserves the dated baseline. Each stable entry ID carries both statuses, a review date, release evidence, notes and links. `topicId` associates it with the existing detailed comparison.

## Sources and limits

- [Publisher FAQ](https://www.tellurionmobile.com/faq/) links the general RealmCraft community wiki. It is not a VR inventory.
- [RealmCraft Wiki mechanics](https://realmcraftgame.fandom.com/wiki/Mechanics) documents the mobile game's mechanics, including brewing. Do not transfer those claims to VR.
- Minecraft Wiki is community-maintained. Readable reference pages: [blocks](https://de.minecraft.wiki/w/Block), [mobs](https://de.minecraft.wiki/w/Kreatur), [brewing](https://de.minecraft.wiki/w/Brauen), [multiplayer](https://de.minecraft.wiki/w/Mehrspieler), [crossbow](https://de.minecraft.wiki/w/Armbrust), [name tag](https://de.minecraft.wiki/w/Namensschild). Some fetched revisions were older indexed copies. Other article URLs serve as reference links, not claims of a fresh successful page fetch. Only established feature existence is compared, not current spawn rules or recipes.
- [Official VR updates](https://steamcommunity.com/app/2943620/allnews/) and [1.0.3 announcement](https://steamcommunity.com/app/2943620/?curator_clanid=4777282) provide release evidence. The older Steam store description is superseded where dated updates conflict.
- [Official VR roadmap](https://realmcraft-vr.canny.io/) lists outstanding work. Controller mapping and damage decals still appeared in progress despite the 1.0.3 release, demonstrating lag. Planned/in-progress entries therefore mean no release established by this review, not proven absence.

## Review after a new release

1. Record the new VR release number, publication date and platform. Compare Minecraft editions only at the level supported by the cited pages.
2. Reopen the linked wiki articles and official release/roadmap evidence. Check features that were planned, in progress, partial or unconfirmed first.
3. A released feature requires affirmative release or reproducible game evidence. Confirmed absence requires an explicit reliable statement scoped to the version/platform. Wiki omission, enum names and a roadmap label alone are insufficient.
4. Update only rechecked entries: statuses, notes, sources, version and checkedAt. The catalog reviewedAt is the date of the overall review, not permission to overwrite every entry's individual date.
5. Preserve this baseline. Create a new dated review folder with the updated JSON and a short change record, then replace the live catalog. Keep stable IDs and valid topicId links.
6. Check unique IDs, valid status values, ISO dates, HTTPS sources, translations and the UI's search/category/status filtering. Build from a stable temporary source snapshot.

No automatic monitor or date-only refresh is configured. The checklist is read-only to users so a checkbox cannot accidentally become evidence of a released feature.
